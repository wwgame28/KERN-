# MASTER PROMPT — COSMIC SANDBOX

Работай над проектом COSMIC SANDBOX согласно `CLAUDE.md`, `docs/GDD_RU.md`, `docs/TECHNICAL_PLAN_RU.md` и `docs/MOBILE_WORKFLOW_RU.md`.

Ты работаешь с пользователем, который управляет процессом только с iPhone и использует Xogot. Поэтому твой результат должен быть пригоден для передачи на телефон и открытия в Xogot. Не требуй от пользователя настольного компьютера или длинных команд терминала без крайней необходимости.

## Перед началом
1. Просмотри весь существующий репозиторий/проект.
2. Определи, есть ли уже Godot-проект и какая версия указана в `project.godot`.
3. Не удаляй существующие файлы без причины.
4. Проверь совместимость проекта с Xogot только на основании доступной информации; неизвестное пометь как требующее проверки.
5. Составь короткий план и приступай к первому этапу.

## Требуемый результат первого этапа
Создай минимальный, но реально запускаемый Godot-проект:
- стартовая сцена;
- простая stylized 3D тестовая планета/площадка;
- персонаж от третьего лица;
- камера;
- мобильное сенсорное управление;
- клавиатура/мышь для будущей PC-версии;
- переключение двух значений гравитации;
- портал-заглушка с интерактивным сообщением;
- README с инструкцией открытия в Xogot.

Если Xogot не поддерживает какой-либо элемент, не ломай проект ради предположения. Объясни ограничение и предложи совместимый вариант.

## Реализация
- Создавай полные файлы, а не псевдокод.
- Проверяй пути и имена ресурсов.
- Не используй функции/классы, которых нет в выбранной версии Godot.
- Не добавляй сторонние плагины на первом этапе.
- Не создавай сложную процедурную генерацию до работающего прототипа.
- Не симулируй каждую частицу физическим телом.
- Временные примитивы допустимы в первом прототипе, но помечай их как placeholder.

## Проверка
Запусти headless/editor checks, если среда это позволяет. Если нет — не делай вид, что запускал. Дай пользователю точный список ручной проверки в Xogot.

## В конце
Подготовь полный ZIP проекта, если среда позволяет создавать архивы. В отчёте укажи:
- список файлов;
- реализованные механики;
- выполненные тесты;
- непроверенные пункты;
- известные ограничения;
- как открыть в Xogot;
- следующий этап.

Начни с аудита и ЭТАПА 1. Не задавай дополнительные вопросы, если можешь сделать безопасные разумные предположения. Если есть блокирующая неизвестная совместимость, задай один конкретный вопрос.
