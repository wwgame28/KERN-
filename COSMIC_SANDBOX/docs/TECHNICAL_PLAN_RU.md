# Технический план COSMIC SANDBOX

## 1. Технологическая база
- Godot 4.x — уточнить точную версию, поддерживаемую установленным Xogot.
- GDScript с типизацией.
- 3D renderer выбирать после проверки совместимости и производительности на устройстве; начать с самого совместимого варианта.
- Проект должен открываться без сторонних плагинов.

## 3. Системные компоненты
### Player
CharacterBody3D, камера, ввод, взаимодействие. Не смешивать ввод, движение и UI в одном скрипте.

### PlanetDefinition
Resource с параметрами планеты: display_name, gravity_strength, gravity_direction, environment_color, scene_path. Проверять ссылки на сцены.

### PlanetManager
Активная планета и применение её параметров к игроку и физическим объектам.

### GravityController
На первом прототипе поддержать два режима силы гравитации. Не реализовывать произвольные поля гравитации до проверки базового движения.

### Portal
Area3D или другая простая зона взаимодействия. На первом этапе — безопасная заглушка с сообщением. Позже — смена планеты с сохранением прогресса.

### SkillSystem
Данные навыков хранить отдельно от UI. Использовать Resource или простые сериализуемые данные.

## 4. Этапы
### Этап 0 — аудит среды
- Узнать версию Xogot и поддерживаемую версию Godot.
- Уточнить, как пользователь импортирует ZIP/папку в Xogot.
- Не предполагать наличие desktop MCP.
- Определить, где Claude будет хранить/редактировать файлы и как передавать их в Xogot.

### Этап 1 — вертикальный срез
- проект Godot;
- стартовая сцена;
- тестовая планета;
- игрок и камера;
- touch controls + keyboard/mouse;
- два режима гравитации;
- интерактивный портал-заглушка.

### Этап 2 — физические эксперименты
- ограниченный набор объектов;
- взрывной импульс;
- базовая реакция материалов;
- простые эффекты огня/воды/электричества/ветра по одному.

### Этап 3 — планетарные данные
- PlanetDefinition;
- переключение двух тестовых планет;
- разные параметры среды;
- загрузка/выгрузка сцен.

### Этап 4 — исследование
- сканер;
- журнал открытий;
- одна пещера;
- одно существо с простым AI.

### Этап 5 — навыки и сюжет
- опыт исследования;
- дерево навыков;
- первые сюжетные находки;
- сохранение прогресса.

### Этап 6 — контент и polish
- кастомизация;
- дополнительные планеты;
- UI;
- звук;
- оптимизация и тестирование.

## 5. Производительность
- Фиксированный бюджет активных физических объектов.
- Использовать StaticBody/простые коллизии для неподвижного окружения.
- Частицы — преимущественно визуальные, не отдельные физические тела.
- Объекты далеко от игрока переводить в упрощённое состояние.
- Ограничивать дальность и количество эффектов.
- Предусмотреть графические пресеты Low/Medium/High.
- Не создавать огромную планету из миллионов отдельных Node3D.
- Не обещать целевой FPS до теста на реальном устройстве.

## 6. Сохранения
После появления игрового прогресса использовать версионируемый формат сохранения. Сохранять открытые планеты, навыки, настройки и сюжетные находки. Проверять обработку отсутствующего/повреждённого файла.

## 7. Критерии качества
- Чистый запуск без ошибок.
- Все Input Actions назначены.
- Нет ссылок на несуществующие ресурсы.
- UI масштабируется под портретный и альбомный экран, если выбранная ориентация это требует.
- Есть понятные состояния загрузки и ошибки.
- Ручной тест в Xogot документирован.
